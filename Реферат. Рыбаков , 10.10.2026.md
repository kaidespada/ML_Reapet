
ООП - парадигма программирования в новых реалиях. 

Парадигма программирования - фундаментальный подход стиль или концептуальный взгляд на то, как должна быть устроена и как должна работать программа в общем и целом.

Паттерн (Шаблон проектирования)  - готовое, типовое решение для часто возникающей узкой проблемы в рамках определенной парадигмы.

|                                                                                                                           |                                                      |                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Категория**                                                                                                             | **Паттерн**                                          | **Суть паттерна в одно предложение**                                                                   |
| **Порождающие** _(Creational)_  <br>Фокус: как создаются объекты. Избавляют код от жесткой привязки к конкретным классам. | **Фабричный метод** _(Factory Method)_               | Определяет единый интерфейс создания объектов, позволяя подклассам выбирать их тип.                    |
|                                                                                                                           | **Абстрактная фабрика** _(Abstract Factory)_         | Создает целые семейства связанных объектов (например, элементы интерфейса для конкретной ОС).          |
|                                                                                                                           | **Строитель** _(Builder)_                            | Позволяет пошагово создавать сложные объекты, используя один и тот же код сборки.                      |
|                                                                                                                           | **Прототип** _(Prototype)_                           | Позволяет копировать существующие объекты, не вдаваясь в подробности их реализации.                    |
|                                                                                                                           | **Одиночка** _(Singleton)_                           | Гарантирует, что у класса есть только один экземпляр, и дает к нему глобальную точку доступа.          |
| **Структурные** _(Structural)_  <br>Фокус: как объекты соединяются друг с другом, образуя крупные, но гибкие структуры.   | **Адаптер** _(Adapter)_                              | Служит переводчиком, позволяя объектам с несовместимыми интерфейсами работать вместе.                  |
|                                                                                                                           | **Мост** _(Bridge)_                                  | Разделяет абстракцию и реализацию, чтобы их можно было изменять независимо.                            |
|                                                                                                                           | **Компоновщик** _(Composite)_                        | Объединяет объекты в древовидную структуру и позволяет работать с деревом как с единым объектом.       |
|                                                                                                                           | **Декоратор** _(Decorator)_                          | Динамически добавляет объектам новые обязанности, оборачивая их в другие объекты.                      |
|                                                                                                                           | **Фасад** _(Facade)_                                 | Предоставляет простой и понятный интерфейс к сложной системе классов или библиотеке.                   |
|                                                                                                                           | **Приспособленец** _(Flyweight)_                     | Экономит память, разделяя общее состояние между множеством мелких объектов.                            |
|                                                                                                                           | **Заместитель** _(Proxy)_                            | Подменяет реальный объект, контролируя доступ к нему (например, для логирования или ленивой загрузки). |
| **Поведенческие** _(Behavioral)_  <br>Фокус: как объекты общаются и распределяют обязанности между собой.                 | **Цепочка обязанностей** _(Chain of Responsibility)_ | Передает запрос по цепочке обработчиков, пока один из них не займется им.                              |
|                                                                                                                           | **Команда** _(Command)_                              | Превращает запросы или действия в отдельные объекты, позволяя ставить их в очередь или отменять.       |
|                                                                                                                           | **Интерпретатор** _(Interpreter)_                    | Определяет грамматику простого языка для решения специфических регулярных задач.                       |
|                                                                                                                           | **Итератор** _(Iterator)_                            | Дает возможность последовательно обходить элементы коллекции, не раскрывая ее внутреннее устройство.   |
|                                                                                                                           | **Посредник** _(Mediator)_                           | Заставляет объекты общаться только через себя, уменьшая прямую зависимость между ними.                 |
|                                                                                                                           | **Хранитель** _(Memento)_                            | Сохраняет и восстанавливает внутреннее состояние объекта, не нарушая инкапсуляцию.                     |
|                                                                                                                           | **Наблюдатель** _(Observer)_                         | Создает механизм подписки, уведомляющий другие объекты об изменениях состояния «издателя».             |
|                                                                                                                           | **Состояние** _(State)_                              | Позволяет объекту менять свое поведение в зависимости от текущего внутреннего состояния.               |
|                                                                                                                           | **Стратегия** _(Strategy)_                           | Инкапсулирует разные алгоритмы в классы и позволяет менять их прямо во время выполнения программы.     |
|                                                                                                                           | **Шаблонный метод** _(Template Method)_              | Задает скелет алгоритма в базовом классе, позволяя подклассам переопределять отдельные шаги.           |
|                                                                                                                           | **Посетитель** _(Visitor)_                           | Позволяет добавлять новые операции к группе классов, не изменяя сами эти классы.                       |
